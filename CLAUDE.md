## Docstrings and code comments

**Do not write docstrings or code comments.**

Self-check before reporting the task as completed: run `git grep` in the repository to confirm you added no new prose.

Create git commits proactively, with one commit per dedicated change, and include a verbose rationale in the commit body.

_Note that ignore comments that suppress false positives (e.g., `# noqa`, `# type: ignore`, `# pragma: nocover`) are obviously out of scope for these guidelines._
