# Benchmark datetime libraries

Compare:

- Python 3.14.7 [`datetime`](https://docs.python.org/3/library/datetime.html)
- [python-dateutil](https://github.com/dateutil/dateutil)
- [arrow](https://github.com/arrow-py/arrow/)
- [pendulum](https://github.com/sdispater/pendulum)
- [udatetime](https://github.com/freach/udatetime)
- [pydantic](https://github.com/pydantic/pydantic) (used only in benchmarks where we parse an argument)
- [pandas](https://pandas.pydata.org/) (used only in benchmarks where we parse an argument)
- [whenever](https://github.com/ariebovenberg/whenever)

There are three types of benchmarks or three types of actions you can do in your code:

- Manipulating datetime, date, duration objects.
- Parsing (for example, converting a string to an object).
- Dumping (for example, converting an object to a string).

## How to run

```sh
uv run -- pytest src/benchmark_datetime --benchmark-group-by=func --benchmark-histogram="benchmark_histogram/"
```

## Results summary

If performance is important:

- Use `whenever` for parsing, dumping, and manipulating dates and times. Its Rust extension is the fastest option in 10 of the 12 benchmarks below, including every parsing and manipulation benchmark except `test_parse_utc_from_iso_8601_duration` and `test_weekday`.
- For ISO 8601 duration parsing, Pydantic and pandas are faster than `whenever`, which needs an extra `ItemizedDelta.parse_iso()` step since its `TimeDelta` type cannot parse mixed date/time ISO durations directly.
- For a plain weekday lookup, Python `datetime`, `udatetime`, and `arrow` are all faster than `whenever`, which has no direct `.weekday()` method and must go through `.date().day_of_week()` instead.

`pendulum` and `arrow` can be several times slower. Use third-party packages if you need additional functionality for manipulating dates, and a possible performance overhead can be ignored, and you are not going to implement these helper functions with a standard library.
